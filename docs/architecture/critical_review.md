# Independent architecture review

Status: **REVIEW COMPLETE; RECOMMENDATIONS NOT APPROVED**. Date: 2026-10-20, Asia/Kolkata.

Read with [proposed architecture](proposed_architecture.md) and [ordered proposed roadmap](proposed_roadmap.md). These documents do not supersede AGENTS.md until the user approves the changes.

## Finding

The project objective is reasonable. The current plan is not an executable research design: it selects several expensive model families before defining experiments, conflates different image domains, and contains conflicting contracts. A task-specific supervised system with small baselines is a better starting point. Diffusion should leave the required implementation scope.

This is an architectural recommendation, not evidence that a particular model will win on this project's data. No model has been trained, timed, or benchmarked here.

## Repository and environment evidence

Inspected all existing project files: AGENTS.md, Context.md, configs/default.yaml, requirements.txt, tests/smoke_test.py, the three package initializers, .gitignore, and data/experiment placeholders.

- Only package docstrings, one YAML configuration, and a permissive smoke script exist. train.py, eval.py, inference.py and all advertised model/loss/data modules are absent.
- data/ and experiments/ contain placeholders; their reported data usage is zero. The documents' descriptions of datasets as “sourced” do not establish local availability.
- Git had no commits; all initial files were untracked. A documentation review branch, codex/architecture-review, was created without staging or committing anything.
- Local hardware reports MacBook Air, Apple M5, 8 GPU cores, 16 GB unified memory; approximately 264 GiB filesystem space was available at inspection. This is shared system memory, not dedicated CUDA VRAM.
- `python` resolves to Miniconda Python 3.13.13; `python3` to system Python 3.9.6. `python -m pip show torch torchvision` found neither in that interpreter. GPU execution and MPS availability in PyTorch therefore remain unverified.
- The user confirmed a strict $0 budget, local MPS for light work, and free Colab/Kaggle GPUs if available. The initial same-day deadline was then relaxed to **this week**; the exact submission timestamp is unconfirmed. A new method or publishable novelty is required academically. Verified non-adversarial pretrained restoration weights may be evaluated separately, with download approval. No cloud allocation is currently verified.

## Requirements versus provisional choices

Preserve: restoration fidelity; no adversarial training or unapproved adversarially trained components; SR x2/x4; real smartphone denoising; AWGN sigma 10–50 and Poisson experiments; concrete artifact removal; RGB public image interfaces; configurable experiments; CPU/MPS/CUDA support; reproducibility and approval gates.

Question: compulsory model families, compulsory perceptual loss, universal tensor ranges/shapes, literal legacy AMP APIs, specific training schedules and folder layout. Some are labeled hard constraints in AGENTS.md, so changing them still requires explicit approval. The [proposal's decision register](proposed_architecture.md#approval-and-decision-register) enumerates them.

## Prioritized critique

## Comparison of alternatives

These are suitability judgments informed by published evidence, not predictions of this project's final ranking. Historical paper results use different data/recipes; they are not interchangeable benchmarks.

| Candidate | Theoretical/task fit and published evidence | Compute, stability, implementation, reproducibility | Recommended role |
|---|---|---|---|
| Restormer | Established Gaussian/real denoising. Channel statistics provide global conditioning, not full pairwise spatial attention. [Paper](https://arxiv.org/abs/2111.09881). | MDTA attention products scale approximately O(N C²/h); projections/FFN also cost O(N C²). “Linear in N for fixed width” does not mean cheap. Deep multiscale model; official code helps reproducibility. | Required transformer comparator for denoising; no SR adaptation in core. |
| SwinIR lightweight | Established x2/x4 reconstruction heads and shifted-window attention. [Paper](https://arxiv.org/abs/2108.10257). | Window attention scales O(N M² C) for window side M, plus projections. Window masks, relative positions and padding are implementation risks. Smaller parameter count does not guarantee lower latency. | Required SR transformer; use the lightweight supervised variant. |
| LDM | Conditional generative restoration is possible, but latent compression and sampling do not guarantee observation fidelity. | Encoder/decoder, conditioning, training objective and sampler are additional systems. Sampling needs repeated denoiser evaluations; accelerated sampling does not remove provenance or fidelity questions. | Deferred research extension with a separate approval and compute plan. |
| DnCNN-style RGB | Residual CNN designed for noise estimation; [DnCNN paper](https://arxiv.org/abs/1608.03981) supports blind Gaussian denoising. | Small, portable and easy to test; batch normalization makes tiny microbatches a concern. L1 here differs from its original training recipe. | Minimal learned denoising baseline, explicitly named dncnn_rgb_l1. |
| EDSR baseline | Residual CNN with LR-space processing and pixel-shuffle SR; [EDSR paper](https://arxiv.org/abs/1707.02921). | Straightforward, stable supervised baseline without batch normalization. Much simpler than a transformer; not inherently inferior for all operating points. | Learned SR baseline, 16 blocks and width 64. |
| NAFNet width32 | Efficient convolutional encoder-decoder with multiplicative gates and pooled channel attention. Strong SIDD evidence in its paper; not a transformer. | Maintainable alternative to Restormer. The [official recipe](https://github.com/megvii-research/NAFNet/blob/main/options/train/SIDD/NAFNet-width32.yml) uses PSNRLoss, so an L1 version is a project adaptation. | First optional challenger, or approved replacement if Restormer exceeds the measured budget. Do not add both automatically. |
| Identity / bicubic / classical denoisers | Identity quantifies input quality; bicubic is essential for SR. BM3D can supply a meaningful nonlearned AWGN reference. | Cheap correctness anchors; color-BM3D provenance, package and noise assumptions require checking. Bilateral filtering alone is a weak research comparator. | Identity and bicubic essential; BM3D optional. |
| FFDNet / larger RCAN | [FFDNet](https://github.com/cszn/FFDNet) supports a noise-map interface; RCAN is an established heavier SR CNN. | Noise maps would expand the current one-RGB-tensor model contract; another large SR baseline adds training cost. | Consider only if conditioning or a stronger CNN becomes the research question. |
| HAT / MambaIR | [HAT](https://arxiv.org/abs/2205.04437) strengthens SR context aggregation; [MambaIR](https://arxiv.org/abs/2402.15648) explores state-space restoration. | Larger study scope. [MambaIR's installation](https://github.com/csguoh/MambaIR) includes CUDA-oriented selective-scan dependencies, a portability concern on this Mac. | Evidence that the original models are not the only alternatives; defer until a specific accuracy/efficiency gap justifies them. No current-SOTA claim. |

## Research question and decision boundaries

The original plan supports an engineering question: under fixed training data and recorded compute, what fidelity/latency/memory tradeoff do compact CNNs and task-specific transformers achieve? A secondary question is how L1, Charbonnier and a frozen feature-loss term change that tradeoff under a declared degradation mismatch. These are useful controls but do not, by themselves, satisfy the user's clarified new-method requirement.

The revised primary research candidate is the explicitly specified JPEG phase-consistency experiment in the proposal, with the engineering baseline as its control. It becomes a reproduction only for a named experiment matching upstream data, initialization, recipe and evaluation. A new architecture, benchmark leadership or publishable novelty is not established. The candidate targets JPEG phase sensitivity; it requires a focused prior-art distinction and empirical evidence before claiming novelty.

The user's clarification creates a material feasibility conflict: a novel-method study plus full training across the original task scope cannot responsibly be promised this week on unallocated free hardware. Small patches, accumulation and AMP reduce resource pressure; they do not guarantee faster convergence, free GPU access or scientific novelty. Two T4s have separate device memory; ordinary data parallelism replicates a model on each GPU rather than combining them into one 30 GB device. Accumulation also does not increase the microbatch seen by batch normalization.

Recommendation: approve a week-scale executable system and one focused candidate-method experiment, with explicit limitations, while retaining the full objective as later phases. The proposed JPEG phase study is a hypothesis, not an established novel contribution; [existing shift-invariant JPEG work](https://openaccess.thecvf.com/content_ICCV_2019/papers/Fu_JPEG_Artifacts_Reduction_via_Deep_Convolutional_Sparse_Coding_ICCV_2019_paper.pdf) makes a novelty claim particularly premature. A thesis requiring proven publishable novelty remains unsatisfied until prior-art review and real evidence support it. JPEG task definition, milestone narrowing and the hard-constraint amendments require approval. No implementation or long run is authorized by this review.

## Review limitations

This is source inspection and literature analysis. No packages, datasets or weights were downloaded; no training or benchmark was run. Some CVF HTML endpoints returned access errors; the papers' arXiv versions and official code were used instead. The LDM PDF exceeded the browser fetch limit; its arXiv HTML and official autoencoder configuration were inspected. Linked upstream main branches can change; implementation must pin commits and checksums before claiming reproducibility.
